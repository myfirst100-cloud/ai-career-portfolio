The Business Challenge

CarCollectorsClub.com Had Outgrown Its Manual Publishing Operations

Managing hundreds of collector-car events, auctions, venues, organizers, articles, dates, images, and social posts required information to move across several systems. Researching new dates, validating records, updating WordPress, maintaining Google Sheets, publishing content, and keeping event data synchronized created repetitive work and opportunities for errors as the operation continued to grow.

The challenge was not simply creating content. It was keeping research, data, publishing, and multiple connected systems accurate, synchronized, and scalable.

The Solution

Replace Disconnected Manual Work With One Connected Operating System

Instead of continuing to solve each task manually, I designed a connected operating system around the publishing process. A custom dashboard became the control center. Behind it, Node.js services, n8n workflows, AI agents, custom scrapers, Google Sheets, webhooks, REST APIs, WordPress, The Events Calendar, and MySQL-backed site data work together to research, validate, enrich, publish, update, and synchronize event information.

The result is a practical production system that reduces repetitive work, improves data consistency, speeds publishing, and gives the business a more scalable way to manage its event and auction operations.

01 · CCC Publisher Dashboard

A Custom Dashboard That Cuts 30+ Hours of Manual Work to Less Than One Hour

CarCollectorsClub.com manages hundreds of collector-car events, auctions, venues, organizers, articles, dates, images, and publishing tasks. I designed the CCC Publisher Dashboard to bring those operations into one visual control center instead of managing them across disconnected tools and manual processes.

The dashboard gives the operator a live view of event data, publishing status, venue and organizer information, WordPress IDs, dates, social-post status, and workflow results. From the same interface, the user can launch AI-assisted and automated workflows that research, validate, update, publish, synchronize, and distribute event information.

02 · Behind the Dashboard

From One Button Click to a Fully Synchronized Content Update

The dashboard is only the control surface. Behind each action is a connected workflow that moves data across the systems required to complete the job.

When the operator selects an existing car show and clicks Update Content & Publish, the dashboard sends the request into the backend automation layer. The workflow retrieves the current event and article data, uses AI where needed to improve and format the content, prepares the updated publishing payload, synchronizes the changes with WordPress and Google Sheets, and returns the result to the dashboard.

The entire process is designed to keep the event record, article content, WordPress data, IDs, metadata, images, and operating data synchronized without requiring the user to manually move between systems.

04 · Automated discovery

Automated Auction Discovery Built for Repeatable, Structured Intelligence

The Problem

Collector-car auction schedules are spread across many websites with different layouts, date formats, naming conventions, and venue details. Manually reviewing those sites and preparing the information for publishing created a repetitive research process that was difficult to scale.

The Solution

I designed a custom auction discovery system that runs site-specific scraper scripts, extracts upcoming auction data, normalizes the results into a consistent structure, and sends newly discovered records into the CCC data and publishing pipeline for validation, enrichment, synchronization, and publishing.

The goal was not simply to scrape webpages — it was to turn changing public auction information into structured, reusable business data.

Working proof

From Live Auction Websites to Structured Event Data

Each site-specific runner visits the target auction website, identifies upcoming auction records, extracts the relevant event details, and converts them into a consistent data structure.

The Mecum example shown here returns structured fields such as auction name, city, date range, organizer ID, normalized end date, source URL, and record key before checking whether the staging data is already current.

The structured output is then available to the connected Google Sheets and n8n workflow layer for downstream validation, enrichment, publishing, and synchronization.

Synchronization Matters as Much as Automation

The value of the system is not simply that individual tasks are automated. The workflows also keep information aligned across the systems that depend on it.

Event records, venue and organizer IDs, publishing data, status information, and returned API results can be written back into the source-of-truth dataset so the next workflow starts with the most current information available.

This closed-loop synchronization reduces repeated data entry and helps prevent the different systems from drifting apart over time.
