# Project Instructions

## README Documentation Standards

After every meaningful project change, review `README.md`.

Update `README.md` only when the change affects:

- project purpose
- architecture
- setup
- commands
- dependencies
- workflows
- integrations
- operating instructions
- current functionality
- known limitations or unfinished areas
- important project structure

Do not rewrite, reformat, or modify unrelated README content.

Do not invent features, integrations, workflows, capabilities, paths, dates, or project information that cannot be verified from the actual project.

Keep `README.md` concise but operationally useful. Document what a new developer or AI agent would need to understand, run, verify, and safely modify the project.

Do not turn `README.md` into a change log.

Whenever `README.md` is actually modified, update:

**README Last Updated:** YYYY-MM-DD HH:MM

Use the current local date and time. If no README content is changed, do not alter the timestamp.

## README Project Metadata

Near the top of `README.md`, directly below the project title, maintain:

**Project Started:** YYYY-MM-DD (**first Git commit date**)  
**Project Path:** `C:\full\current\path\to\project`  
**README Last Updated:** YYYY-MM-DD HH:MM

- Determine `Project Started` from the project's actual first Git commit and do not change it during normal README updates.
- Verify the current full local path before writing `Project Path`; update it if the project is moved or renamed.
- Set `README Last Updated` only when the README is actually modified, using the current local date and time.
- If `README.md` does not exist, create it only when specifically authorized or when the current task explicitly requires project documentation to be created.
